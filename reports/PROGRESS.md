### Real production data restored
The user supplied `Prints.zip` — extracted to `import/Prints/` (not committed): **34 DXF sheets `FC1000495-0xx`, 33 DWG, 1 `FC1000495_AFR.ACD`**.

The `.ACD` is **not** an AutoCAD Electrical project database — its header reads *"This file was generated by the RSLogix 5000 software"*: it is a **Studio 5000 / RSLogix 5000 PLC program** (ASCII text, 4.8 MB), sitting in a `PLC\` folder. What the 34 DXFs actually contain (measured):

- Real ACADE symbol blocks: `BOX`(137), `DOT`(75), `TERMINAL`(64), `Ground`(52), `CONT-NO`(37), `TY`(28), `PT`(26), `WDDOT`(22), `PLUG`/`Plug`, `PB-NC`, `PB-NO`, `ELGND`, `24VDCPRX`, `PHONEJACK`, `ELCB`, `Arrow-l`, `FAN`.

- **The sheets carry no attributes on their symbol inserts** (only `WD_M` and the 12 module blocks do). Component tags exist only as plain `TEXT` — 5,776 model-space texts. That, not file I/O, is why only 4 components are found on the one sheet that does resolve.

**The project's numbering contract, read from `WD_M` (uniform on 34/34 sheets):**

| Attribute | Value | Meaning |
|---|---|---|
| `TAGFMT` | `%F%N` | component tag = family + number |
| `TAGMODE` | `R` | reference-based |
| `TAG-START` | `1` | first number |
| `TAG-RSUF` | `,A,B,C,D,E,F,G,H,J` | suffix sequence |
| `REFNUMS` | `1` | reference numbering mode |
| `WIREFMT` | `%N` | wire number = sequential number |
| `WIREMODE` | `R` | reference-based |
| `WIRE-START` | `1`, `WIRE-RSUF` `,A..N` | wire number start + suffixes |
| `XREFFMT`, `ALT_XREFFMT` | `%N` | cross-reference format |
| `WNUM_FLAGS` 1, `RUNGHORV` H, `PH3SPACE` 0.5, `DISTH`/`DISTV` 2.0 | | layout settings |

This is the real, project-specific answer to "what should ELECNUMBER/ELECWIRELIST produce" — no licence needed, the data was in the customer's own drawings.

Verified: `ELECINSERT FUSE` → `placed FUSE as -F1`, then `ELECLIST` lists `Fuse -F1`.

### The drawing configures the layer (`WD_M`)
- **`ELECSETUP`** (new command) prints the drawing's tag/wire/xref format, mode, start value, suffixes and the library status. On a real sheet:
  `tag %F%N mode R (existing references are fixed) start 1 suffixes A,B,C,D,E,F,G,H,J · wire %N mode R · xref %N`.
- **`ELECNUMBER`** takes `TAGFMT`/`TAG-START` from `WD_M` and, when `TAGMODE`/`WIREMODE` is `R`, **freezes existing references**. This retires the round-1 safety warning: on `FC1000495-003` the preview changed from "would rename `M326` to `M1`" to **"would write 0 tag(s)"**.

- **`ELECLIST`/`ELECBOM`** report the symbol's class from the loaded library (`CONT-NO` → `Contactor`) instead of its block name.

## Round 4 — 2026-11-06 (wire processing)

### Wires are nets now, not "loose drafting"
`crates/elec/src/geometry.rs` gained `netlist_from_geometry_with_wire_runs()`: a connected run of wires is an equipotential whether or not a symbol sits on it, so the run now appears in `nets` (with an empty anchor list) instead of being counted as loose. The strict `netlist_from_geometry()` is unchanged, so the existing 121 crate tests still pass (**verified: 121 passed, 0 failed**), and `ELECWIRELIST` / `ELECWIRENUMBER` / `ELECJUNCTIONS` / `ELECIO` use the lenient one.

Measured on the customer sheets:
- `FC1000495-046`: **77 wire segment(s) → 21 net(s)** (was 48 one-wire "nets" before T-junctions), largest net **34 wires**.
- `FC1000495-003`: **132 segments, 4 components → 57 nets**, with a 34-wire and a 22-wire net; the wire list reports `unconnected: HYD. UNIT, M326, M326, M326`, and `ELECWIRENUMBER` now **numbers the nets** (it previously refused with "no connected nets found").
- **T-junctions merge too**: a wire ending on the middle of another wire (what a junction dot means) is now the same net, using the measured 0.02-unit gap, while 0.125-unit symbol-pin gaps and wire-hop arcs stay separate. This is what turned dozens of one-segment nets into real connection nets.

Still not anchored: symbol **pins**. On the customer sheets the symbols were exploded, so there is nothing to anchor a net to; the 4 surviving attribute devices are reported as unconnected because their insertion points are not on a wire.

### A reported bug that turned out to be already fixed
`ELECINSERT` giving the same tag to consecutive placements no longer reproduces: three consecutive inserts now report `-K1`, `-K2`, `-K3`. The cause was the same collector divergence — tags were counted in model space while the new symbols landed on a layout sheet, so the counter never saw them. The all-space collector fix closed it.

Devices, Terminals, Cross-reference, Cables, Reports, Project & sheet). It is reachable from
the ribbon too (Project & Sheet -> Drawing -> Command Reference), and every line names a
command the dispatcher really handles, so the reference cannot drift silently.
