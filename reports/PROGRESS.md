### Real production data restored
The user supplied `Prints.zip` — extracted to `import/Prints/` (not committed): **34 DXF sheets `FC1000495-0xx`, 33 DWG, 1 `FC1000495_AFR.ACD`**.

The `.ACD` is **not** an AutoCAD Electrical project database — its header reads *"This file was generated by the RSLogix 5000 software"*: it is a **Studio 5000 / RSLogix 5000 PLC program** (ASCII text, 4.8 MB), sitting in a `PLC\` folder. Useful as a real PLC I/O reference; not an ECAD import format.

What the 34 DXFs actually contain (measured):
- Every sheet carries **two identical `WD_M` inserts** — the ACADE per-sheet setup block, **77 attribute settings**, uniform on **34/34 sheets**.
- Real ACADE symbol blocks: `BOX`(137), `DOT`(75), `TERMINAL`(64), `Ground`(52), `CONT-NO`(37), `TY`(28), `PT`(26), `WDDOT`(22), `PLUG`/`Plug`, `PB-NC`, `PB-NO`, `ELGND`, `24VDCPRX`, `PHONEJACK`, `ELCB`, `Arrow-l`, `FAN`.
- Electrical layers already in use: `WIRES`(84), `SYMS`(65), `TERMS`(22), `TAGS`(14), `DESC`, `XREF`, `LOC`, `DESCCHILD`, `TITLE_BLOCK`.
- **The sheets carry no attributes on their symbol inserts** (only `WD_M` and the 12 module blocks do). Component tags exist only as plain `TEXT` — 5,776 model-space texts. That, not file I/O, is why only 4 components are found on the one sheet that does resolve.

**The project's numbering contract, read from `WD_M` (uniform on 34/34 sheets):**

| Attribute | Value | Meaning |
|---|---|---|
| `TAGFMT` | `%F%N` | component tag = family + number |
| `TAGMODE` | `R` | reference-based |
| `TAG-START` | `1` | first number |
| `TAG-RSUF` | `,A,B,C,D,E,F,G,H,J` | suffix sequence |
| `REFNUMS` | `1` | reference numbering mode |
| `WIREFMT` | `%N` | wire number = sequential number |
| `WIREMODE` | `R` | reference-based |
| `WIRE-START` | `1`, `WIRE-RSUF` `,A..N` | wire number start + suffixes |
| `XREFFMT`, `ALT_XREFFMT` | `%N` | cross-reference format |
| `WNUM_FLAGS` 1, `RUNGHORV` H, `PH3SPACE` 0.5, `DISTH`/`DISTV` 2.0 | | layout settings |

This is the real, project-specific answer to "what should ELECNUMBER/ELECWIRELIST produce" — no licence needed, the data was in the customer's own drawings.

### Research landed
- [`ecad-conventions.md`](ecad-conventions.md) — symbol licensing (QElectroTech CC-BY 3.0 is the usable seed; KiCad CC-BY-SA as a separate pack; IEC/IEEE sets are paid), IEC 81346 product prefix is `-`, and a sharp ACADE interop boundary: `WD_M` + the `%F %N %S %X` format language are **documented**; the component attribute schema (`TAG1`, `TERM01`…) is de-facto; XDATA/extension-dictionary usage and `.dwg` custom objects are **not** documented. Honest maximum claim = "ACADE-compatible DXF profile v1, unvalidated".
- `reports/library-bootstrap.md` and `reports/skycad-model.md` — in flight when this entry was written.

### Safety note before the next round
- **Do not run `ELECNUMBER` (apply) on the customer's real sheets.** On `FC1000495-003` its preview says it *would* rewrite the real `M326` tags to `M1` (3 changed) and skip `-H` as structured. Preview is safe; apply is destructive until numbering reads the real tags.
- **Unit scale mismatch:** the sheets are ~35.5 × 25.1 units per A3 with symbols 0.06–1.25 units, text 0.125, while the drafting aids assume millimetres (junction dot radius 1.0, wire-number height 2.5, `ELECINSERT` step 40, `ELECSHEET` paper 420×297). A 10–20× mismatch — the frame lands at 1:10 on real sheets.
